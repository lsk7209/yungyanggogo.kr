영양고고(yungyanggogo.kr)의 기존 사이트 개선을 시작해줘.

함께 제공한 01_MASTER_PROMPT.md를 실행 명세로, 02_ACCEPTANCE_TESTS.md를 완료 기준으로 사용해. 우선 두 파일을 읽고 현재 저장소가 실제 영양고고 프로젝트인지 확인해. 다른 저장소면 수정하지 마.

목표는 기존 도메인·데이터·정상 기능을 보존하면서 공개 오류, 데이터 정확성, 검색·비교 사용성, 콘텐츠 중복, 기술 SEO와 광고 정책 적용을 개선하는 것이다. 분석 문서만 작성하고 끝내지 말고 작업 브랜치에서 가능한 코드 수정과 테스트까지 진행해.

핵심 규칙:
1. 저장소·현재 코드·실제 응답을 확인한 사실과 이전 진단의 가설을 구분해.
2. 약 400개 글·31만 데이터 같은 이전 수치를 현재 글 수·공개 URL 수·Google 색인 수로 단정하지 마.
3. 30~50개 글은 편집 규모의 예시일 뿐이다. 정해진 개수를 맞추려고 삭제·자동 생성하지 마.
4. noindex는 검색 색인 정책이지 AdSense 품질 문제의 면제 수단이 아니다. 공개 상태·색인·광고를 각각 제어해.
5. 기존 사용자 변경과 원본 데이터를 보존하고, 대량 변경은 결정표·dry-run·롤백을 먼저 만들어.
6. 운영 배포, 운영 DB 쓰기, DNS/계정/유료서비스 변경은 별도 승인 없이 실행하지 마.
7. 작성자·영양사·편집팀·제품 순위·검토일·게시자 ID를 만들어내지 마. AI 확인을 사람 검수로 표시하지 마.
8. 영양 법정 기준은 시행일과 적용 범위를 공식 원문에서 확인해. 확인 불가한 기준 충족 배지는 중지하고 미결로 남겨.
9. API 파서·COUNT·원천 중복·결측/0·g/ml·기준량·100kcal 0분모를 테스트로 고쳐.
10. API 실패를 결과 없음이나 전체 0건으로 바꾸지 말고, 마지막 정상 스냅샷과 출처를 보존해.

진행 순서:
저장소·URL·데이터 감사 → 공개 개발정보/잘못된 주장 제거 → 데이터 QC·파서 수정 → 검색·상세·2~3개 비교 완성 → 대표 주제군 콘텐츠 개선 → URL별 통합/색인 결정표 → canonical/sitemap/광고/접근성 검증 → 최종 테스트·운영 반영/롤백 문서.

작업 이력은 docs/quality 아래에 남겨. 권한이나 자료가 없는 항목은 blocked 또는 NOT RUN으로 기록하고, 독립적으로 가능한 작업은 계속해. 통계 랭킹·대형 관리자·개인화 추천 같은 P2 기능을 늘리느라 P0/P1을 미루지 마.

최종 보고에는 수정 파일, 확인된 문제, 변경 전후 상태, 실행한 명령, PASS/FAIL/NOT RUN, 남은 사람 검수와 계정 설정, 운영 반영 전제 및 롤백 절차를 구분해. AdSense 승인 보장이나 실제 확인하지 않은 작업 완료는 말하지 마.

지금 대상 확인과 짧은 실행계획부터 작성한 뒤, 안전한 작업 범위 내에서 구현을 진행해.
